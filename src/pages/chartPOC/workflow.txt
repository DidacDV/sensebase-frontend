# Energy Data System Explanation

## 1. Overall Flow: How the Process Works

```
User Request → React Component → Service Layer → API/Mock Data
                     ↓
              Helper Functions
                     ↓
              Formatted Data
                     ↓
              Nivo Chart Component
                     ↓
              Visual Chart
```

### Step-by-Step Process:

1. **User visits the page** → React component mounts
2. **Component calls service** → `energyService.getConsumptionBySource('ALL', 'monthly')`
3. **Service fetches data** → Either from API or mock JSON
4. **Raw data returned** → Complex nested JSON structure
5. **Helper transforms data** → `transformToNivoBarData(sourceData)`
6. **Formatted data** → Simple array ready for charts
7. **Nivo renders chart** → Visual representation

---

## 2. Service Layer Functions Explained

### `energyService.getEnergyData(granularity, startDate, endDate)`

**Purpose**: Fetch the complete energy dataset

**What it does**:
```typescript
// Currently returns mock data
// Future: Will make HTTP request to your API
const data = await fetch(`/api/energy?granularity=monthly`)
```

**Returns**: The entire JSON structure with CONSUMPTION → ALL/GRID/LOCAL → Categories

**When to use**: When you need the complete dataset (rarely needed directly)

---

### `energyService.getConsumptionBySource(source, granularity)`

**Purpose**: Get data for a specific source (ALL, GRID, or LOCAL)

**What it does**:
```typescript
// Gets only the part you need
data.CONSUMPTION['ALL'] // Returns ALL source data
// or
data.CONSUMPTION['GRID'] // Returns GRID source data
```

**Returns**: An object with categories: Total, Lighting, IT, Mixed usages, No usage

**When to use**: When you want to visualize all categories from one source

---

### `energyService.getUsageCategoryData(source, category, granularity)`

**Purpose**: Get data for one specific category (like only "Lighting")

**What it does**:
```typescript
// Drills down to specific category
data.CONSUMPTION['ALL']['Lighting']['Active energy delivered']
```

**Returns**: Array with timeSeriesValues for that specific category

**When to use**: When you need data for a single category (Total consumption only, Lighting only, etc.)

---

## 3. Helper Functions Explained

### `formatMonth(dateString)`

**Purpose**: Convert ISO date to readable format

**Input**: `"2025-01-01T00:00:00.000+01:00"`

**Output**: `"Jan 2025"`

**Why needed**: Nivo needs simple strings for x-axis labels

---

### `whToKwh(wh)`

**Purpose**: Convert Watt-hours to Kilowatt-hours

**Input**: `6537678` (Wh)

**Output**: `6537.678` (kWh)

**Why needed**: kWh is more readable for humans (smaller numbers)

---

### `transformToNivoBarData(sourceData, categories)`

**Purpose**: Transform complex nested data into Nivo's expected format

**Input** (complex nested structure):
```json
{
  "Lighting": {
    "Active energy delivered": [{
      "timeSeriesValues": [
        { "startTime": "2025-01-01...", "value": 768779 },
        { "startTime": "2025-02-01...", "value": 754069 }
      ]
    }]
  },
  "IT": { ... },
  "Mixed usages": { ... }
}
```

**Output** (Nivo-friendly array):
```json
[
  { "month": "Jan 2025", "Lighting": 768.779, "IT": 591.617, "Mixed usages": 5177.282 },
  { "month": "Feb 2025", "Lighting": 754.069, "IT": 552.019, "Mixed usages": 4754.249 }
]
```

**How it works**:
1. Creates a Map to organize data by month
2. Loops through each category (Lighting, IT, Mixed usages)
3. For each time value, gets the month and adds category data
4. Converts values to kWh
5. Returns array of month objects

**Why this format**: Nivo Bar expects each object to represent one x-axis item (month) with all y-axis values (categories) as properties

---

### `transformTotalConsumption(energyData)`

**Purpose**: Simpler transformation for single-value charts

**Input**:
```json
[{
  "timeSeriesValues": [
    { "startTime": "2025-01-01...", "value": 6537678 },
    { "startTime": "2025-02-01...", "value": 6060337 }
  ]
}]
```

**Output**:
```json
[
  { "month": "Jan 2025", "consumption": 6537.678 },
  { "month": "Feb 2025", "consumption": 6060.337 }
]
```

**When to use**: For charts showing only one metric over time

---

### `calculateEnergyIntensity(energyData, area)`

**Purpose**: Calculate consumption per square meter (or other unit)

**Input**: 
- Energy data
- Area: `1000` (m²)

**Output**:
```json
[
  { "month": "Jan 2025", "intensity": 6.537 },  // kWh/m²
  { "month": "Feb 2025", "intensity": 6.060 }
]
```

**Why useful**: Normalizes consumption by building size for comparison

---

### `getConsumptionStats(energyData)`

**Purpose**: Calculate summary statistics

**Output**:
```json
{
  "total": 48709.947,    // Total kWh for all months
  "average": 6088.743,   // Average monthly kWh
  "max": 6682.634,       // Highest month
  "min": 4277.0          // Lowest month
}
```

**When to use**: For dashboard summary cards

---

### `compareSourceConsumption(source1Data, source2Data, labels)`

**Purpose**: Compare two sources side-by-side

**Output**:
```json
[
  { "month": "Jan 2025", "Grid": 6537.678, "Local": 1200.5 },
  { "month": "Feb 2025", "Grid": 6060.337, "Local": 1150.3 }
]
```

**When to use**: To visualize Grid vs Local consumption

## 4. How Nivo Charts Work

### Basic Concept:
Nivo expects data in a specific format where:
- Each object = one item on the x-axis
- Properties = values for different bars/lines

### Nivo Bar Chart Data Format:

```typescript
// For STACKED or GROUPED bars
data = [
  { x_axis_label: "Jan", category1: 100, category2: 200, category3: 150 },
  { x_axis_label: "Feb", category1: 120, category2: 180, category3: 160 }
]

// Configuration
keys = ['category1', 'category2', 'category3']  // What to display
indexBy = 'x_axis_label'  // What to use for x-axis
```

### Different Nivo Chart Types Need Different Formats:

#### **Bar Chart** (ResponsiveBar):
```json
[
  { "month": "Jan", "value1": 100, "value2": 200 }
]
```

#### **Line Chart** (ResponsiveLine):
```json
[
  {
    "id": "Lighting",
    "data": [
      { "x": "Jan", "y": 768 },
      { "x": "Feb", "y": 754 }
    ]
  },
  {
    "id": "IT",
    "data": [
      { "x": "Jan", "y": 591 },
      { "x": "Feb", "y": 552 }
    ]
  }
]
```

#### **Pie Chart** (ResponsivePie):
```json
[
  { "id": "Lighting", "value": 768, "label": "Lighting" },
  { "id": "IT", "value": 591, "label": "IT" }
]
```

#### **Heatmap** (ResponsiveHeatMap):
```json
[
  {
    "id": "Lighting",
    "data": [
      { "x": "Jan", "y": 768 },
      { "x": "Feb", "y": 754 }
    ]
  }
]
```

## 5. Creating New Chart Styles

### Yes, you need new helper functions for different chart types!

Each Nivo chart expects data in its own format, so you'd create helpers like:

```typescript
// For Line Chart
export const transformToNivoLineData = (sourceData: SourceData) => {
  // Returns format: [{ id: "Lighting", data: [{ x, y }] }]
}

// For Pie Chart
export const transformToNivoPieData = (sourceData: SourceData, month: string) => {
  // Returns format: [{ id: "Lighting", value: 768 }]
}

// For Heatmap
export const transformToNivoHeatmapData = (sourceData: SourceData) => {
  // Returns format: [{ id: "category", data: [{ x, y }] }]
}
```

### Example: Creating a Line Chart Helper

```typescript
export const transformToNivoLineData = (
  sourceData: SourceData,
  categories: (keyof SourceData)[]
): Array<{ id: string; data: Array<{ x: string; y: number }> }> => {
  
  return categories.map(category => {
    const energyData = sourceData[category]["Active energy delivered"];
    
    return {
      id: category,
      data: energyData[0].timeSeriesValues
        .filter(ts => ts.value !== null && ts.value !== 0)
        .map(ts => ({
          x: formatMonth(ts.startTime),
          y: whToKwh(ts.value)
        }))
    };
  });
};
```
